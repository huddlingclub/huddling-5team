# 커피내기 머지 게임 PRD

Nov 14, 2026 · @Yullie

## 개요

직장인 2\~5명이 방 코드 하나로 모여, 커피 테마 머지 퍼즐을 동시에 플레이하고 최저 점수자가 커피를 사는 웹 게임이다. 설치·회원가입 없이 링크로 1분 안에 시작하는 것이 핵심 가치다. 이 문서는 비개발자 팀이 각자 쓰는 AI 코딩 도구로 나눠 만들어 2시간 안에 실제로 한 판 돌아가는 MVP를 만드는 것을 기준으로 한다. 코드는 AI 도구가 쓰고, 팀원은 요청·확인·계정 설정만 한다.

- **타깃**: 점심 직후·오후 티타임에 커피 살 사람을 정하려는 같은 팀 직장인
- **플레이 방식**: 각자 자기 폰 화면에서 개인 게임판을 플레이하고, 점수만 실시간으로 공유한다 (Fruit Clash식 낙하·합치기 메커니즘 차용)
- **세션 성격**: 일회성. 계정·영구 저장 없이 게임이 끝나면 방이 사라진다
- **플랫폼**: Vercel에 배포한 웹페이지. 팀원은 링크로 폰·PC 브라우저에서 접속 (계정 불필요)

**성공 지표 (출시 후 4주)**

| 지표 | 목표 |
| --- | --- |
| 방 생성 → 게임 시작 전환율 | 70% 이상 |
| 코드 입력 → 입장 소요 시간 | 중앙값 15초 이하 |
| 게임 종료 후 "한 판 더" 비율 | 30% 이상 |
| 게임 중 연결 끊김 비율 | 2% 이하 |

## 게임 흐름

호스트는 설정 후 코드를 받고, 참가자는 코드나 공유 링크로 들어와 대기실에서 합류한다. 결과 화면의 "한 판 더"는 같은 멤버·같은 설정으로 대기실로 돌아간다.

입장은 서버가 코드 존재, 남은 자리, 게임 진행 여부를 확인한 뒤에만 허용된다.

## 게임 룰

같은 음료 두 잔이 닿으면 다음 단계 음료 한 잔으로 합쳐지고, 제한 시간이 끝났을 때 점수가 가장 낮은 사람이 커피를 산다.

**머지 단계와 점수**

| 단계 | 음료 | 낙하 등장 | 합쳐질 때 점수 | 상대 크기 |
| --- | --- | --- | --- | --- |
| 1 | 원두 | 등장 (확률 50%) | — | 1.0 |
| 2 | 에스프레소 | 등장 (확률 30%) | +2 | 1.4 |
| 3 | 아이스 아메리카노 | 등장 (확률 20%) | +5 | 1.9 |
| 4 | 라떼 | 미등장 | +12 | 2.5 |
| 5 | 커피 프라페 | 미등장 | +30 | 3.2 |
| 6 | 유니콘 프라페 | 미등장 | +80 | 4.0 |

점수는 "그 단계 음료가 만들어질 때" 더한다. 등장 확률·점수·크기는 초기값이며 플레이 테스트로 조정한다. 유니콘 두 잔이 만나면 둘 다 사라지고 +200점 보너스를 준다(최종 단계 처리).

**게임오버와 종료**

- 컵(게임판) 상단의 경고선을 음료가 2초 이상 넘으면 그 플레이어는 게임오버, 그 시점 점수로 확정된다
- 게임오버된 사람은 남은 시간 동안 다른 사람 점수판을 관전한다
- 방 전체 종료 조건: 제한 시간 종료, 또는 모든 플레이어 게임오버 중 먼저 오는 것

**승패 판정 (커피 살 사람)**

1. 최종 점수가 가장 낮은 1명이 커피 담당
2. 최저 점수 동점이면 먼저 게임오버된 사람이 담당
3. 그래도 동점(둘 다 시간 종료까지 생존)이면 최고 단계 음료가 낮은 사람
4. 그래도 같으면 랜덤으로 1명 선정 (룰렛 연출은 이후)

**방 설정 범위**

| 항목 | 범위 | 기본값 | 입력 방식 |
| --- | --- | --- | --- |
| 인원수 | 2\~5명 | 4명 | 스테퍼 |
| 제한 시간 | 30초\~5분 | 2분 | 30초 단위 선택 (30초, 1분, 1분 30초 … 5분) |

인원수는 "최대 인원"이다. 설정 인원이 다 차면 자동으로 입장이 막히고, 호스트는 2명 이상이면 인원이 덜 찼어도 시작할 수 있다.

## 추가 기능: 2콤보 방해요소

2콤보를 만들면 상대에게 방해요소를 보낸다. 방해요소 종류는 아직 정하지 않았고, 아래 후보 중 플레이 테스트로 고른다. 2시간 MVP 다음 1순위로 붙인다.

**규칙 (제안)**

| 항목 | 제안 | 상태 |
| --- | --- | --- |
| 콤보 정의 | 음료 하나를 떨어뜨린 뒤 1.5초 안에 머지가 2번 이상 연속으로 일어남 (연쇄 머지 포함) | 제안, 시간 창은 테스트로 조정 |
| 발동 | 2콤보 달성 시 방해요소 1개 | 미정: 3콤보 이상일 때 더 보낼지 |
| 받는 사람 | 현재 1위 / 무작위 1명 / 나를 뺀 전원 | 미정 |
| 방해요소 종류 | 아래 후보 중 선택 | 미정 |
| 쿨다운 | 같은 사람이 3초 안에 방해요소를 2번 받지 않음 | 제안 |
| 게임오버한 사람 | 보내지도 받지도 않음 | 제안 |

**방해요소 후보**

| 후보 | 받는 사람 화면에서 생기는 일 | 구현 난이도 |
| --- | --- | --- |
| 원두 투하 | 컵 위에서 원두 2\~3개가 떨어짐 | 낮음 |
| 컵 흔들기 | 컵이 1초 흔들려 음료 배치가 흐트러짐 | 낮음 |
| 미리보기 가리기 | 5초 동안 다음 음료가 안 보임 | 낮음 |
| 얼음 큐브 | 합쳐지지 않는 얼음 블록 1개가 떨어지고 10초 뒤 녹아 사라짐 | 중간 |
| 경고선 내리기 | 5초 동안 경고선이 한 칸 낮아짐 | 중간 |

**정해야 할 것**

- [ ] 방해요소 종류 (1개로 시작할지, 여러 개 중 무작위로 할지)
- [ ] 받는 사람 규칙
- [ ] 콤보 시간 창 (1.5초 제안)
- [ ] 3콤보 이상 보상

**구현 메모**: `engine.js`가 콤보를 감지하면 `onCombo` 콜백으로 `App.jsx`에 알리고, `useRoom.js`가 `attack` 메시지를 보낸다. 받는 쪽은 `App.jsx`가 `engine.js`의 방해요소 함수를 불러 자기 화면에서 실행한다. 방해요소 종류·콤보 시간·쿨다운은 `src/game/constants.js`의 `ATTACK_TYPES` 등에 모아 두어, 종류가 정해지면 값만 추가하면 되게 한다. 콤보는 드물게 나오므로 Supabase 메시지 한도에는 거의 영향이 없다.

## 개발 환경

React + Tailwind CSS를 Vite로 만들고, GitHub에 올리면 Vercel이 빌드해서 배포한다. 실시간 동시 접속은 Supabase Realtime이 맡는다. 빌드 도구를 쓰므로 각자 컴퓨터에 Node.js가 필요하지만, 설치·실행 명령은 AI 코딩 도구가 대신 실행한다.

| 영역 | 팀 공통 선택 | 각자 할 일 |
| --- | --- | --- |
| AI 코딩 도구 | 자유 (Claude Code, Cursor, GitHub Copilot 등) | 작업 시작 시 도구에게 `AGENTS.md`를 먼저 읽게 하기 |
| 프레임워크 | React (함수형 컴포넌트 + Hooks), JavaScript(JSX) | 없음 |
| 스타일 | Tailwind CSS v4 (Vite 플러그인), 커피 테마 디자인 토큰 | 토큰에 없는 색·크기 쓰지 않기 |
| UI 컴포넌트 | shadcn/ui (`src/components/ui/`). 그 밖의 UI 라이브러리는 쓰지 않음 | 새 컴포넌트가 필요하면 먼저 알리기 |
| 빌드 도구 | Vite | AI 도구에 "npm install 하고 개발 서버 켜줘"라고 요청 |
| 실행 환경 | Node.js LTS (`.nvmrc`로 버전 고정), 패키지 관리는 npm만 | 사전 준비 때 Node.js 설치 |
| 게임 물리 | matter.js (npm 패키지) | 없음 |
| 실시간 | @supabase/supabase-js, 방 코드마다 채널 1개 (Broadcast + Presence) | 없음 |
| 코드 보관 | GitHub 저장소 1개, 팀원 모두 협업자 | 저장소 초대 수락 |
| 배포 | Vercel Pro 팀. Vite 프로젝트를 자동 인식해 빌드, 브랜치마다 미리보기 주소 생성 | Vercel 팀 초대 수락 |
| 환경 변수 | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. 로컬은 `.env.local`, 배포는 Vercel 프로젝트 설정에 등록 | 대표가 공유한 값으로 `.env.local` 만들기 |
| 데이터베이스 | 쓰지 않음 (테이블·SQL 없음) | 없음 |
| 확인 방법 | 로컬 개발 서버(`npm run dev`) 또는 Vercel 미리보기 주소에서 PC + 폰으로 확인 | 본 것을 그대로 AI 도구에 전달 |

**미리 할 일 (시작 전 40분)**: 대표 1명이 GitHub 저장소, Vercel Pro 팀, Supabase 프로젝트를 만들고 팀원을 초대한다. 이어서 AI 도구로 프로젝트 뼈대를 만든다("Vite React 프로젝트에 Tailwind CSS v4, matter.js, supabase-js를 설치하고 PRD의 폴더 구조대로 빈 파일을 만들어줘"). 이 뼈대를 `main`에 올리고 Vercel 배포와 환경 변수 등록까지 확인한다. 팀원은 Node.js LTS를 설치하고, 저장소를 받아 `npm install`과 `npm run dev`로 첫 화면이 뜨는지 확인한다. Vercel 무료(Hobby) 플랜은 비공개 저장소에서 소유자 본인 커밋만 배포되므로 팀 작업에는 Pro가 필요하다([Vercel 안내](https://vercel.com/kb/guide/why-aren-t-commits-triggering-deployments-on-vercel)).

**키 관리**: `VITE_`로 시작하는 환경 변수는 브라우저에 그대로 노출된다. 그래서 Supabase의 공개 키(anon/publishable)만 넣고, service\_role·secret 키는 어디에도 넣지 않는다. `.env.local`은 GitHub에 올리지 않고, 변수 이름만 적은 `.env.example`을 올린다.

**참가자 조건**: 링크만 있으면 누구나 접속한다. 앞선 아티팩트 방식과 달리 claude.ai 계정이 필요 없다.

**왜 실시간을 Vercel에서 하지 않나**: Vercel도 이제 WebSocket을 지원하지만, 연결이 서버 인스턴스 하나에 묶이고 기본 300초 제한이 있다. 여러 명에게 같은 메시지를 뿌리려면 Redis 같은 저장소를 직접 붙여야 해서 비개발자 2시간 범위를 넘는다. 게임 1판(최대 5분)에 대기 시간까지 더하면 300초를 넘길 수도 있다. ([Ably 비교 글](https://ably.com/vercel/vercel-websockets-vs-ably), Vercel 문서 인용)

**AI 도구에게 요청하는 법**: 한 번에 한 기능만 요청하고, 내 담당 파일만 고치게 한다. 버그는 "무엇을 했고, 무엇을 기대했고, 실제로 무엇이 보였는지"를 적고 가능하면 스크린샷을 붙인다. 잘 되는 버전이 나오면 "내 브랜치에 커밋하고 올려줘"라고 말한다.

**Supabase 무료 한도와 점수 전송 빈도**: 무료 플랜은 동시 연결 200개, 초당 메시지 100개다([Supabase Realtime 한도](https://supabase.com/docs/guides/realtime/limits)). 메시지는 받는 사람 수만큼 세므로, 5명 방에서 각자 1초에 1번 점수를 보내면 방 하나가 초당 약 25개를 쓴다. 그래서 점수는 1초에 최대 1번 보내고, 무료 플랜에서 5명 방은 동시에 3\~4개까지로 본다.

**에셋**: MVP는 색 원과 글자로만 표현한다. 원두\~유니콘 일러스트는 출시 전 직접 만들거나 디자이너에게 맡긴다. Fruit Clash의 그림·사운드·UI는 쓰지 않는다(리스크 섹션 참고).

## 팀 공통 개발 규칙

도구가 달라도 결과물이 섞이지 않게, 규칙은 저장소의 `AGENTS.md` 한 파일에 두고 모든 AI 도구가 그것을 따르게 한다. 파일마다 담당자를 정해 같은 파일을 동시에 고치지 않는다.

**코드 규칙**

| 항목 | 팀 규칙 |

## 서버 설계 (Supabase Realtime)

DB 없이 Supabase Realtime 채널 하나로 방을 만든다. 방 정보는 호스트의 Presence(접속 상태)에 담고, 점수·시작·결과는 Broadcast로 주고받으며, 타이머 종료와 커피 담당 판정은 호스트 기기가 한다.

Broadcast 메시지는 중간에 빠질 수 있어서 점수는 "+5" 같은 증가분이 아니라 "현재 총점"을 보낸다. 방 정보가 호스트 Presence에 있으므로, 호스트가 나가면 방이 사라진다. MVP에서는 그 판을 무효로 하고 다시 시작한다.

**방 정보 (채널 `room:{방 코드}`의 Presence)**

| 누구의 Presence | 값 | 설명 |
| --- | --- | --- |
| 호스트 | role: host, status: lobby / playing / finished | 방 단계. 입장 가능 여부 판단에 사용 |
| 호스트 | maxPlayers 2\~5, durationSec 30\~300 | 호스트 설정 |
| 호스트 | startsAt, endsAt | 모두 같은 기준으로 카운트다운·남은 시간 표시 |
| 참가자 (호스트 포함) | nickname, joinedAt | 대기실 목록, 입장 순서 |

Presence는 한 사람이 30초에 5번까지만 바꿀 수 있어서, 점수처럼 자주 바뀌는 값은 넣지 않는다.

**Broadcast 메시지**

| 메시지 | 내용 | 보내는 사람 · 때 |
| --- | --- | --- |
| start | startsAt, endsAt | 호스트, 시작 버튼 누를 때 (Presence status도 playing으로 변경) |
| score | 현재 총점, 최고 단계, 생존 여부 | 각자, 점수가 바뀌었을 때 1초에 최대 1번 |
| gameOver | 최종 점수, 게임오버 시각 | 각자, 경고선 2초 초과 시 |
| finished | 순위, 커피 담당 닉네임 | 호스트, 종료 확정 시 (Presence status도 finished로 변경) |
| attack (추가 기능) | 보낸 사람, 받는 사람, 방해요소 종류 | 각자, 2콤보 달성 시 |

**코드로 입장할 때 확인 순서**

| 순서 | 확인 | 결과 |
| --- | --- | --- |
| 1 | 채널 `room:{코드}`에 접속하고 2초 동안 Presence 목록을 받는다 | — |
| 2 | 호스트가 없다 | "없는 코드예요" |
| 3 | 호스트 status가 lobby가 아니다 | "이미 시작된 방이에요" |
| 4 | 참가자 수가 maxPlayers와 같다 | "방이 꽉 찼어요" |
| 5 | 모두 통과 | 내 Presence 등록, 대기실 입장 |

**타이머·공정성·방 코드**

2시간 MVP에 넣는 것:

- 모든 기기가 같은 endsAt으로 남은 시간을 보여주고, 호스트 기기가 endsAt이 지나면 종료를 확정한다
- 커피 담당은 호스트 기기가 마지막으로 받은 점수로 계산해 finished로 알린다
- 방 코드는 31자(0·O·1·I·L 제외) 6자리. 만들 때 같은 코드 채널에 이미 호스트가 있으면 다시 뽑는다
- 점수 조작 방어는 하지 않는다 (사내 친선 내기 전제)

이후로 미루는 것:

- 호스트가 나가면 다음 입장자가 방 정보를 이어받기
- 연결 끊김 후 재접속
- 전적·팀별 "커피 많이 산 사람" 랭킹이 필요하면 Supabase 데이터베이스 테이블 추가
- 공개 버전에서 점수 검증이 필요하면 Supabase Edge Functions로 서버 판정
