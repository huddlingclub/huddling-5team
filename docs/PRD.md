# 커피내기 머지 게임 PRD

Nov 14, 2026 · @Yullie

## 개요

직장인 2\~5명이 방 코드 하나로 모여, 커피 테마 머지 퍼즐을 동시에 플레이하고 최저 점수자가 커피를 사는 웹 게임이다. 설치·회원가입 없이 링크로 1분 안에 시작하는 것이 핵심 가치다. 이 문서는 비개발자 팀이 각자 쓰는 AI 코딩 도구로 나눠 만들어 2시간 안에 실제로 한 판 돌아가는 MVP를 만드는 것을 기준으로 한다. 코드는 AI 도구가 쓰고, 팀원은 요청·확인·계정 설정만 한다.

- **타깃**: 점심 직후·오후 티타임에 커피 살 사람을 정하려는 같은 팀 직장인
- **플레이 방식**: 각자 자기 폰 화면에서 개인 게임판을 플레이하고, 점수만 실시간으로 공유한다 (Fruit Clash식 낙하·합치기 메커니즘 차용)
- **세션 성격**: 일회성. 계정·영구 저장 없이 게임이 끝나면 방이 사라진다
- **플랫폼**: Vercel에 배포한 웹페이지. 팀원은 링크로 폰·PC 브라우저에서 접속 (계정 불필요)

**성공 지표 (출시 후 4주)**

| 지표 | 목표 |
|---|---|
| 방 생성 → 게임 시작 전환율 | 70% 이상 |
| 코드 입력 → 입장 소요 시간 | 중앙값 15초 이하 |
| 게임 종료 후 "한 판 더" 비율 | 30% 이상 |
| 게임 중 연결 끊김 비율 | 2% 이하 |

## 게임 흐름

호스트는 설정 후 코드를 받고, 참가자는 코드나 공유 링크로 들어와 대기실에서 합류한다. 결과 화면의 "한 판 더"는 같은 멤버·같은 설정으로 대기실로 돌아간다.

![게임 흐름 · 호스트·참가자 경로가 대기실에서 합류](https://www.figma.com/spec/g3W8aGvP24RYlx33TYJyd5/image/7ac259d6242efe455eaed7f261f2ebdd77a3f0ff?w=1314&h=432)

입장은 서버가 코드 존재, 남은 자리, 게임 진행 여부를 확인한 뒤에만 허용된다.

## 게임 룰

같은 음료 두 잔이 닿으면 다음 단계 음료 한 잔으로 합쳐지고, 제한 시간이 끝났을 때 점수가 가장 낮은 사람이 커피를 산다.

**머지 단계와 점수**

| 단계 | 음료 | 낙하 등장 | 합쳐질 때 점수 | 상대 크기 |
|---|---|---|---|---|
| 1 | 원두 | 등장 (확률 50%) | — | 1.0 |
| 2 | 에스프레소 | 등장 (확률 30%) | +2 | 1.4 |
| 3 | 아이스 아메리카노 | 등장 (확률 20%) | +5 | 1.9 |
| 4 | 라떼 | 미등장 | +12 | 2.5 |
| 5 | 커피 프라푸치노 | 미등장 | +30 | 3.2 |
| 6 | 유니콘 프라푸치노 | 미등장 | +80 | 4.0 |

점수는 "그 단계 음료가 만들어질 때" 더한다. 등장 확률·점수·크기는 초기값이며 플레이 테스트로 조정한다. 유니콘 두 잔이 만나면 둘 다 사라지고 +200점 보너스를 준다(최종 단계 처리).

**게임오버와 종료**

- 컵(게임판) 상단의 경고선을 음료가 2초 이상 넘으면 그 플레이어는 게임오버, 그 시점 점수로 확정된다
- 게임오버된 사람은 남은 시간 동안 다른 사람 점수판을 관전한다
- 방 전체 종료 조건: 제한 시간 종료, 또는 모든 플레이어 게임오버 중 먼저 오는 것

**승패 판정 (커피 살 사람)**

1. 최종 점수가 가장 낮은 1명이 커피 담당
2. 최저 점수 동점이면 먼저 게임오버된 사람이 담당
3. 그래도 동점(둘 다 시간 종료까지 생존)이면 최고 단계 음료가 낮은 사람
4. 그래도 같으면 랜덤으로 1명 선정 (룰렛 연출은 이후)

**방 설정 범위**

| 항목 | 범위 | 기본값 | 입력 방식 |
|---|---|---|---|
| 인원수 | 2\~5명 | 4명 | 스테퍼 |
| 제한 시간 | 30초\~5분 | 2분 | 30초 단위 선택 (30초, 1분, 1분 30초 … 5분) |

인원수는 "최대 인원"이다. 설정 인원이 다 차면 자동으로 입장이 막히고, 호스트는 2명 이상이면 인원이 덜 찼어도 시작할 수 있다.

## 방해 요소

2콤보 이상을 내면 모든 상대방 컵에 동시에 장애물이 떨어지고, 장애물은 그 근처에서 커피가 합쳐지면 사라진다. 점수 경쟁에 '공격'과 '수습'을 더해 꼴찌도 뒤집을 수 있게 하는 장치다.

**공격 규칙**

1. **콤보**: 합체가 일어난 뒤 1.5초 안에 다음 합체가 일어나면 콤보가 이어진다. 합체로 생긴 음료가 연쇄로 다시 합쳐져도 같은 콤보로 센다
2. **발동**: 콤보가 2 이상인 채로 끊기면, **끊긴 순간 한 번에 공격을 보낸다**
3. **장애물 수**: (콤보 수 − 1)개, 최대 3개. 2콤보 = 1개, 3콤보 = 2개, 4콤보 이상 = 3개
4. **대상**: 나를 뺀 모든 상대방에게 동시에. 게임오버된 사람은 받지도, 보내지도 않는다
5. **낙하**: 받은 사람의 컵 상단 랜덤 가로 위치에서 0.3초 간격으로 떨어진다. "지민님이 장애물 2개를 보냈어요" 알림을 1.5초 띄운다

**장애물 규칙**

- **모양**: 납작한 초콜릿 판(기본 1종). 크기는 에스프레소와 비슷한 폭, 두께는 절반
- **합체 불가**: 음료와도, 다른 장애물과도 합쳐지지 않고 공간만 차지한다
- **삭제**: 장애물 가장자리에서 40px 안에서 커피 합체가 일어나면 그 장애물이 사라진다. 합체 한 번에 근처 장애물이 여러 개면 모두 사라진다. 삭제 점수는 없다
- **게임오버 판정 포함**: 장애물이 경고선을 2초 넘어도 게임오버다
- **상한**: 한 컵에 장애물은 최대 5개. 넘치는 만큼은 버린다

**게임 숫자 (`js/constants.js`)**

| 상수 | 초기값 | 뜻 |
|---|---|---|
| COMBO\_WINDOW\_MS | 1500 | 콤보가 이어지는 시간 |
| ATTACK\_MIN\_COMBO | 2 | 공격이 발동하는 최소 콤보 |
| MAX\_OBSTACLES\_PER\_ATTACK | 3 | 한 번에 보내는 최대 장애물 수 |
| OBSTACLE\_CLEAR\_RADIUS\_PX | 40 | 이 거리 안 합체 시 장애물 삭제 |
| MAX\_OBSTACLES\_IN\_CUP | 5 | 한 컵에 쌓일 수 있는 장애물 수 |
| OBSTACLE\_DROP\_GAP\_MS | 300 | 여러 개가 떨어질 때 간격 |

**모듈 사이 역할**: `game.js`는 콤보가 끊길 때 `onCombo(count)`를 호출하고, `addObstacles(n)`으로 장애물을 받는다. `room.js`는 `attack` 메시지만 주고받고, `ui.js`는 알림만 띄운다.

**이후에 더할 장애물 후보**: 커피 찌꺼기(작은 알갱이 여러 개), 시럽(5초 동안 컵 안이 끈적해짐), 우유 붓기(닿은 음료와 섞임).

## 개발 환경

AI 코딩 도구는 각자 쓰던 것을 쓰고, 언어·파일 구조·규칙 파일·Git 흐름을 팀 전체가 맞춘다. 코드를 GitHub에 올리면 Vercel이 자동 배포하고, 실시간 동시 접속은 Supabase Realtime이 맡는다. 빌드 과정이 없는 HTML·JavaScript 구성이라 개발 도구 설치가 필요 없다.

| 영역 | 팀 공통 선택 | 각자 할 일 |
|---|---|---|
| AI 코딩 도구 | 자유 (Claude Code, Cursor, GitHub Copilot 등) | 작업 시작 시 도구에게 `AGENTS.md`를 먼저 읽게 하기 |
| 언어 | JavaScript (ES 모듈) + HTML + CSS. TypeScript·React·빌드 도구는 쓰지 않음 | 없음 |
| 라이브러리 | matter.js, supabase-js를 CDN에서 정확한 버전으로 고정해 불러옴 | 버전을 바꾸지 않기 |
| 코드 보관 | GitHub 저장소 1개, 팀원 모두 협업자(collaborator) | GitHub 계정, 저장소 초대 수락 |
| 배포 | Vercel Pro 팀 1개에 프로젝트 연결, 브랜치마다 미리보기 주소 자동 생성 | Vercel 팀 초대 수락 |
| 실시간 동시 접속 | Supabase 프로젝트 1개, 방 코드마다 채널 1개 (Broadcast + Presence) | 없음 (대표 1명이 관리) |
| 데이터베이스 | 쓰지 않음 (테이블·SQL 없음) | 없음 |
| 확인 방법 | 각자 브랜치의 Vercel 미리보기 주소에서 PC + 폰으로 확인 | 본 것을 그대로 AI 도구에 전달 |

**미리 할 일 (시작 전 20분)**: 대표 1명이 GitHub 저장소, Vercel Pro 팀, Supabase 프로젝트를 만들고 팀원을 초대한다. 팀원은 초대를 수락하고 자기 AI 코딩 도구를 저장소에 연결한다. Vercel 무료(Hobby) 플랜은 비공개 저장소에서 소유자 본인 커밋만 배포되므로 팀 작업에는 맞지 않는다([Vercel 안내](https://vercel.com/kb/guide/why-aren-t-commits-triggering-deployments-on-vercel)). 회사 업무용 사용 조건 측면에서도 Pro가 안전하다.

**키 관리**: Supabase의 공개 키(anon/publishable)는 브라우저에 넣어도 되는 키라 `config.js`에 둔다. service\_role·secret 키는 절대 코드에 넣지 않는다.

**참가자 조건**: 링크만 있으면 누구나 접속한다. 앞선 아티팩트 방식과 달리 claude.ai 계정이 필요 없다.

**왜 실시간을 Vercel에서 하지 않나**: Vercel도 이제 WebSocket을 지원하지만, 연결이 서버 인스턴스 하나에 묶이고 기본 300초 제한이 있다. 여러 명에게 같은 메시지를 뿌리려면 Redis 같은 저장소를 직접 붙여야 해서 비개발자 2시간 범위를 넘는다. 게임 1판(최대 5분)에 대기 시간까지 더하면 300초를 넘길 수도 있다. ([Ably 비교 글](https://ably.com/vercel/vercel-websockets-vs-ably), Vercel 문서 인용)

**AI 도구에게 요청하는 법**: 한 번에 한 기능만 요청하고, 내 담당 파일만 고치게 한다. 버그는 "무엇을 했고, 무엇을 기대했고, 실제로 무엇이 보였는지"를 적고 가능하면 스크린샷을 붙인다. 잘 되는 버전이 나오면 "내 브랜치에 커밋하고 올려줘"라고 말한다.

**Supabase 무료 한도와 점수 전송 빈도**: 무료 플랜은 동시 연결 200개, 초당 메시지 100개다([Supabase Realtime 한도](https://supabase.com/docs/guides/realtime/limits)). 메시지는 받는 사람 수만큼 세므로, 5명 방에서 각자 1초에 1번 점수를 보내면 방 하나가 초당 약 25개를 쓴다. 그래서 점수는 1초에 최대 1번 보내고, 무료 플랜에서 5명 방은 동시에 3\~4개까지로 본다.

**에셋**: MVP는 색 원과 글자로만 표현한다. 원두\~유니콘 일러스트는 출시 전 직접 만들거나 디자이너에게 맡긴다. Fruit Clash의 그림·사운드·UI는 쓰지 않는다(리스크 섹션 참고).

## 팀 공통 개발 규칙

도구가 달라도 결과물이 섞이지 않게, 규칙은 저장소의 `AGENTS.md` 한 파일에 두고 모든 AI 도구가 그것을 따르게 한다. 파일마다 담당자를 정해 같은 파일을 동시에 고치지 않는다.

**코드 규칙**

| 항목 | 팀 규칙 |
|---|---|
| 언어 | JavaScript (ES 모듈, `<script type="module">`). 다른 언어·프레임워크 추가 금지 |
| 라이브러리 버전 | 처음 정한 CDN 주소의 정확한 버전으로 고정, 바꿀 때는 팀 합의 |
| 이름 짓기 | 변수·함수 camelCase, 상수 UPPER\_SNAKE\_CASE, 파일명 소문자 |
| 형식 | 들여쓰기 스페이스 2칸, 세미콜론 사용, 작은따옴표 |
| 주석 | 한국어. 함수마다 "무엇을 하는지" 한 줄 |
| 화면 문구 | 모두 `js/strings.js`에 모음. 코드 안에 문구 직접 쓰지 않기 |
| 게임 숫자 | 음료 단계·점수·크기·확률·시간 범위는 모두 `js/constants.js`에만 |
| AI 규칙 파일 | `AGENTS.md`가 기준. `CLAUDE.md`, `.cursor/rules`, `.github/copilot-instructions.md`에는 "AGENTS.md를 따른다"는 내용만 둠 |

**파일 구조와 담당**

| 파일 | 내용 | 담당 |
|---|---|---|
| `AGENTS.md` | 팀·AI 공통 규칙 | 대표 |
| `index.html` | 화면 4개(홈·대기실·플레이·결과) 뼈대 | 화면 |
| `css/style.css` | 스타일 | 화면 |
| `js/config.js` | Supabase URL·공개 키 | 대표 |
| `js/constants.js` | 음료 6단계, 점수, 방 설정 범위 | 게임 (바꿀 때 공유) |
| `js/protocol.js` | Presence·Broadcast 메시지 이름과 필드 | 실시간 (바꿀 때 전원 합의) |
| `js/game.js` | 물리·낙하·머지·점수·게임오버 | 게임 |
| `js/room.js` | Supabase 채널, 방 만들기·입장·메시지 송수신 | 실시간 |
| `js/ui.js` | 화면 전환, 대기실·점수판·결과 표시 | 화면 |
| `js/strings.js` | 화면 문구 | 화면 |
| `js/main.js` | 위 모듈을 서로 연결 | 실시간 |

2명이면 화면 담당 파일을 둘이 나눠 맡고, 1명이 더 있으면 게임 담당을 둘로 나눈다(물리·머지 / 점수·게임오버).

**모듈 사이 약속**: `game.js`는 화면과 네트워크를 모르고, 점수가 바뀌면 `main.js`가 넘겨준 함수만 호출한다. `room.js`는 게임 규칙을 모르고 `protocol.js`의 메시지만 주고받는다. `ui.js`는 받은 값을 그리기만 한다. 이렇게 나누면 각자 자기 파일만 고쳐도 합칠 때 충돌이 적다.

**Git 작업 흐름**

1. `main` 브랜치는 항상 동작하는 상태로 두고, 직접 올리지 않는다
2. 작업 시작 전 "main 최신으로 받아줘"라고 AI 도구에 요청한다
3. 작업마다 브랜치를 만든다. 이름은 `이름/기능` (예: `jimin/score-board`)
4. 올리면 Vercel이 그 브랜치의 미리보기 주소를 만든다. 거기서 PC·폰으로 확인한다
5. Pull Request를 열고, 다른 1명이 미리보기 주소로 확인한 뒤 `main`에 합친다
6. 남의 담당 파일을 고쳐야 하면 먼저 담당자에게 말한다

**`AGENTS.md` 시작본** (대표가 0:00에 저장소에 올림)

```markdown
# 커피내기 머지 게임 - 팀 규칙
- 언어: JavaScript(ES 모듈) + HTML + CSS. 빌드 도구, TypeScript, React 금지
- 라이브러리: index.html의 CDN 고정 버전만 사용. 새 라이브러리 추가 금지
- 형식: 스페이스 2칸, 세미콜론, 작은따옴표, camelCase, 한국어 주석
- 화면 문구는 js/strings.js, 게임 숫자는 js/constants.js에만 둔다
- 메시지 이름·필드는 js/protocol.js를 따른다. 임의로 추가·변경 금지
- 요청받은 담당 파일만 수정한다. 다른 파일 수정이 필요하면 먼저 알려준다
- main에 직접 커밋하지 않는다. 작업 브랜치에 커밋한다
- secret 키를 코드에 넣지 않는다 (Supabase 공개 키만 js/config.js에)
```

**AI 도구 세션 시작 문장 (공통)**: "AGENTS.md와 PRD를 먼저 읽어줘. 나는 \[게임/실시간/화면\] 담당이고, \[담당 파일\]만 수정해줘."

## 서버 설계 (Supabase Realtime)

DB 없이 Supabase Realtime 채널 하나로 방을 만든다. 방 정보는 호스트의 Presence(접속 상태)에 담고, 점수·시작·결과는 Broadcast로 주고받으며, 타이머 종료와 커피 담당 판정은 호스트 기기가 한다.

> 도식(원본 문서 참고): 서비스 구조 · Claude Code → GitHub → Vercel, 실시간은 Supabase

Broadcast 메시지는 중간에 빠질 수 있어서 점수는 "+5" 같은 증가분이 아니라 "현재 총점"을 보낸다. 방 정보가 호스트 Presence에 있으므로, 호스트가 나가면 방이 사라진다. MVP에서는 그 판을 무효로 하고 다시 시작한다.

**방 정보 (채널 `room:{방 코드}`의 Presence)**

| 누구의 Presence | 값 | 설명 |
|---|---|---|
| 호스트 | role: host, status: lobby / playing / finished | 방 단계. 입장 가능 여부 판단에 사용 |
| 호스트 | maxPlayers 2\~5, durationSec 30\~300 | 호스트 설정 |
| 호스트 | startsAt, endsAt | 모두 같은 기준으로 카운트다운·남은 시간 표시 |
| 참가자 (호스트 포함) | nickname, joinedAt | 대기실 목록, 입장 순서 |

Presence는 한 사람이 30초에 5번까지만 바꿀 수 있어서, 점수처럼 자주 바뀌는 값은 넣지 않는다.

**Broadcast 메시지**

| 메시지 | 내용 | 보내는 사람 · 때 |
|---|---|---|
| start | startsAt, endsAt | 호스트, 시작 버튼 누를 때 (Presence status도 playing으로 변경) |
| score | 현재 총점, 최고 단계, 생존 여부 | 각자, 점수가 바뀌었을 때 1초에 최대 1번 |
| gameOver | 최종 점수, 게임오버 시각 | 각자, 경고선 2초 초과 시 |
| finished | 순위, 커피 담당 닉네임 | 호스트, 종료 확정 시 (Presence status도 finished로 변경) |

**코드로 입장할 때 확인 순서**

| 순서 | 확인 | 결과 |
|---|---|---|
| 1 | 채널 `room:{코드}`에 접속하고 2초 동안 Presence 목록을 받는다 | — |
| 2 | 호스트가 없다 | "없는 코드예요" |
| 3 | 호스트 status가 lobby가 아니다 | "이미 시작된 방이에요" |
| 4 | 참가자 수가 maxPlayers와 같다 | "방이 꽉 찼어요" |
| 5 | 모두 통과 | 내 Presence 등록, 대기실 입장 |

**타이머·공정성·방 코드**

2시간 MVP에 넣는 것:

- 모든 기기가 같은 endsAt으로 남은 시간을 보여주고, 호스트 기기가 endsAt이 지나면 종료를 확정한다
- 커피 담당은 호스트 기기가 마지막으로 받은 점수로 계산해 finished로 알린다
- 방 코드는 31자(0·O·1·I·L 제외) 6자리. 만들 때 같은 코드 채널에 이미 호스트가 있으면 다시 뽑는다
- 점수 조작 방어는 하지 않는다 (사내 친선 내기 전제)

이후로 미루는 것:

- 호스트가 나가면 다음 입장자가 방 정보를 이어받기
- 연결 끊김 후 재접속
- 전적·팀별 "커피 많이 산 사람" 랭킹이 필요하면 Supabase 데이터베이스 테이블 추가
- 공개 버전에서 점수 검증이 필요하면 Supabase Edge Functions로 서버 판정

## 비기능 요구사항 · 리스크 · 마일스톤

가장 큰 리스크는 기술이 아니라 이름이다. "프라푸치노"는 스타벅스 상표라서 음료 이름을 바꿔야 한다.

**비기능 요구사항**

- 성능: 중급 안드로이드 폰에서 끊김 없이 플레이, 컵 안 음료 최대 60개 기준
- 호환: iOS Safari, Android Chrome 최신 버전 (실제 폰으로 꼭 확인)
- 용량: Supabase 무료 플랜 기준 5명 방 동시 3\~4개, 점수 전송은 1초에 1번
- 개인정보: 닉네임·점수 외 저장 정보 없음 (DB를 쓰지 않음)
- 업무 환경: 소리 없음, 1판 최대 5분
- 이후: 재접속, 동시 방 수가 늘면 Supabase 유료 플랜

**리스크와 대응**

| 리스크 | 영향 | 대응 |
|---|---|---|
| "프라푸치노"는 스타벅스 등록 상표, "유니콘 프라푸치노"는 스타벅스 한정 메뉴명 | 상표 분쟁 | 일반명으로 변경. 예: 커피 프라페 → 유니콘 프라페, 또는 블렌디드·쉐이크 |
| Fruit Clash와 화면·그림·연출이 비슷해 보임 | 저작권·디자인 분쟁 | 낙하·합치기 규칙만 차용, 그림·UI·사운드는 자체 제작 |
| 팀원마다 AI 도구가 달라 코드 스타일·구조가 섞임 | 합칠 때 충돌, 버그 | `AGENTS.md` 규칙 공유, 파일별 담당, Pull Request마다 1명 확인 |
| AI 도구가 요청 안 한 파일까지 고침 | 남의 작업 덮어쓰기 | 세션 시작 문장으로 담당 파일 제한, PR에서 바뀐 파일 목록 확인 |
| Vercel 무료(Hobby) 플랜은 비공개 저장소에서 소유자 커밋만 배포 | 팀원 작업이 배포되지 않음 | Vercel Pro 팀 사용 (멤버 수에 따라 비용) |
| Supabase 무료 한도 초과 (초당 메시지 100개) | 점수판 끊김 | 점수 1초 1번 전송, 동시 방이 많아지면 유료 플랜 |
| secret 키가 코드에 들어감 | 보안 사고 | 공개 키(anon/publishable)만 사용, AI 도구에도 secret 키는 주지 않기 |
| 호스트가 판정하므로 점수 조작 가능 | 내기 신뢰 하락 | 사내 친선 내기 전제로 감수, 공개 버전에서 서버 검증 도입 |
| 2시간 안에 다 못 만듦 | 시연 실패 | 아래 컷 라인 적용, 계정·초대는 미리 끝내기 |

이 표는 법률 자문이 아니다. 정식 출시 전 상표·저작권은 전문가 확인을 권한다.
